# Release notes for 0.1.0

This is a draft for the initial eagle-harness release, not a publication announcement. It describes merged source
features. Final engine builds, install pins and release qualification remain pending. Performance evidence lives
in the [measured support matrix](../support-matrix.md), not in release-wide speed claims.

## Serving and draft models

- Install eagle-harness as an out-of-tree SGLang or vLLM plugin. Hook checks refuse registration when the host
  interface is missing or incompatible.
- Serve EAGLE-4 drafts with the low-rank candidate head and tree-aware GDN verification for hybrid targets.
  Matching cost tables control SGLang draft depth and verify width, and vLLM draft-depth stopping.
- Select vLLM chain widths from measured draft/verify costs and acceptance profiles. High-load behavior still needs a
  matched no-spec comparison.
- Use SGLang Mamba2 tree-verification convolution through the engine extension. This alone does not include the
  real Nemotron draft integration or qualify its performance.

## Request correctness

- Return vLLM logprobs in accepted tree-path order rather than physical verify-row order.
- Serve SGLang accepted-token, top-k and input logprobs with the matching host fixes or documented eager workaround.
- Sample vLLM tree verification from the target distribution and preserve request-slot indexing during chunked
  verification. SGLang sampled-filter correctness requires the corresponding host fix.
- Use root-only tree verification for vLLM grammar-constrained batches. This preserves constraints without
  promising accelerated constrained decoding.
- Order SGLang prelaunch publication and request-slot reads before scheduler filtering, merging and slot reuse.
  The fence follows result-copy work rather than delaying that work behind the next draft.
- Pass dense parent lists to the SGLang tree kernel to avoid the batched draft-selection crash.

## Calibration, tests and packaging

The installed `eagle-harness calibrate` command detects the engine, preserves raw measurements, refuses an
existing output directory and writes a serving command only after successful output checks. The public vLLM
measurement/fitting driver is included. The SGLang served-chain driver remains a separate integration dependency.

The source includes correctness checks for greedy output, sampling, mixed stop conditions, draft attention and
concurrent verification. GDN recurrence code has clearer tensor-layout and ownership documentation without an
intended numerical change. Wheel/source packaging and CI are present, but their existence is not proof that
release assets have been published or installed on a clean machine.

## Before deploying

Read [installation](../install.md), [known limits](../known-limits.md) and the matching
[SGLang CUDA](../quickstart-sglang.md), [SGLang ROCm](../quickstart-amd.md),
[vLLM](../quickstart-vllm.md) or [experimental TokenSpeed](../quickstart-tokenspeed.md) quickstart.
The selected package versions and distribution destinations are in `docs/release.env`. Their presence does not
assert that artifacts have been published. AMD ROCm and CUDA-only TokenSpeed are included in the release source,
with qualification restricted to the configurations in the [support matrix](../support-matrix.md).
Real Nemotron draft integration and the deferred optimizations in [known limits](../known-limits.md) remain
outside that support contract. Final artifact installation and serving checks remain publication gates.
