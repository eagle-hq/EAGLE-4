# EAGLE-4 0.1.3

EAGLE-4 combines a draft model with `eagle-harness` inside your inference engine to adapt speculative decoding to your hardware, batch and workload. Version 0.1.3 brings native decoding at high load to the SGLang README command, including the one-GPU setup, and fills draft KV without prediction work for prompts admitted above the verify limit. It also builds engine wheels and release images from approved inputs and explains how to warm up a server before measuring it.

This release ships SGLang CUDA `0.5.23.dev252+eagle.9`, keeps vLLM `0.32.0rc1.dev283+eagle.4` unchanged, and adds TokenSpeed `0.1.1+eagle.8`, built from [eagle-hq/tokenspeed `eagle/v0.1.3`](https://github.com/eagle-hq/tokenspeed/tree/eagle/v0.1.3). The TokenSpeed engine exposes generic engine hooks, and EAGLE-4 policy and tree verification live in the harness plugin. TokenSpeed serves EAGLE-4 in serve mode from cost tables you calibrate once on your setup. On four B300 GPUs this build passed calibration, greedy serving from the calibrated profile (twenty prompts: 3 identical to TokenSpeed without speculation, 17 first divergences within the fp32 tolerance, the same in two starts) and sampled serving at temperature 1. TokenSpeed's 0.1.2 speed measurements remain historical results, not measurements of this build.

## Install

You don't need to download anything from the release page. In a Python 3.12 environment, install the SGLang packages together:

```bash
pip install "eagle-harness[sglang]==0.1.3" "sglang==0.5.23.dev252+eagle.9" \
  --extra-index-url https://eagle-hq.github.io/EAGLE-4/whl/cu130/ \
  --extra-index-url https://download.pytorch.org/whl/cu130 \
  --extra-index-url https://pypi.nvidia.com
```

Follow the [SGLang guide](../quickstart-sglang.md), [vLLM guide](../quickstart-vllm.md) or [TokenSpeed guide](../quickstart-tokenspeed.md) to serve an EAGLE-4 draft. Install TokenSpeed with its matching scheduler, kernel and control-plane wheels using the [install guide](../install.md#tokenspeed-cuda). The TokenSpeed image is `:0.1.3`; SGLang and vLLM keep their documented `:0.1.2` images until their `:0.1.3` image checks finish.

## Limits

The release correctness check compares each EAGLE-4 output with the same engine's output without speculation on the same prompts, and judges every first difference against an fp32 recomputation of that position. Across the four SGLang configurations, 12,089 of 12,096 checked outputs (prompts over starts and concurrency levels) pass. Of the 15 outputs that first fell outside the tolerance, 8 carry a token that plain decoding on the same engine build, recipe and tensor-parallel size also emits at the exact prefix, in a replay batch no larger than the tested concurrency. Numerical thresholds stay unchanged. Seven outputs remain outside the tolerance:

- SGLang README command on one GPU at 128 concurrent requests: one prompt in each of four starts.
- SGLang measured recipe on four GPUs at 64 concurrent requests: one prompt in each of two starts.
- SGLang high-load recipe on four GPUs at 512 concurrent requests: one prompt in one start.

The vLLM measured recipe passes its release correctness check. Version 0.1.4 will compare against plain decoding at the same batch size.

On the four-GPU SGLang README command at 8 concurrent requests, 0.1.3 reaches 0.97× the throughput of 0.1.2 (2,549.3 against 2,624.1 output tokens per second, four starts each), below the 0.98× release threshold. The speed measurements cover the model, commands and GPU counts above. SGLang's high-load recipe measures 0.98× plain-decoding throughput at 128 concurrent requests, and some other high-load cells are slightly below 1.00×. This release makes no claim that speculation is faster for every workload.

TokenSpeed static mode (`"mode": "static"`) stops at server start with the released EAGLE-4 draft, whose attention layer uses a 4096-token sliding window. The TokenSpeed 0.1.3 engine has no sliding-window path for draft trees yet. Serve mode runs the draft tree in `eagle-harness` and is the supported TokenSpeed path. Static-mode support is planned for 0.1.4. The [known limits](../known-limits.md) describe the remaining engine and request-feature constraints.
